API Reference

JSON REST and WebSocket API served by the ProxyGate admin listener. Every /api/* endpoint except /api/auth/* requires authentication, as does /ws; unauthenticated calls get 401. Requests are accepted only from allowed_networks, rate limited to 1000 requests / 60s per IP, and bodies are capped at 256 KiB. Cross-origin writes and WebSocket upgrades are rejected (403). Errors are returned as { "error": "message" } with 400 (validation), 401, 404, 409 (conflict), 429 or 500. Requests refused by the network allowlist (403) or the general rate limiter (429) get a plain-text body.

Base URL: http://127.0.0.1:9090/api

Authentication

Browsers sign in and receive an HttpOnly, SameSite=Strict session cookie. Scripts send an API token created on the machine with proxygate token create <name>:

curl -H "Authorization: Bearer pgt_…" http://127.0.0.1:9090/api/routes

Setup, sign-in and password changes are limited to 5 failures per address per 15 minutes (429 with Retry-After). With security.require_secure_login they are refused (403) unless the connection is HTTPS or from localhost. See Security.

GET /api/auth/status Whether setup is needed and the caller is signed in

Response

{
  "setup_required": false,
  "authenticated": true,
  "strong_password_policy": true,
  "https": false,
  "insecure_transport": false,
  "require_secure_login": false
}

insecure_transport is true when the page is plain HTTP and the caller is not on localhost. While setup is required, setup_code_path names the file holding the one-time code.

POST /api/auth/setup Set the first admin password with the one-time setup code

Request Body

{ "setup_code": "XXXXX-XXXXX-XXXXX-XXXXX", "password": "…", "strong_password_policy": true }

Signs the caller in. 401 for a wrong code, 409 once a password exists, 400 if the password breaks the chosen rules.

POST /api/auth/login Sign in and receive a session cookie

Request Body

{ "password": "…" }

401 for a wrong password, 409 if setup has not been completed.

POST /api/auth/logout End the current session
POST /api/auth/password Change the admin password

Request Body

{ "current_password": "…", "new_password": "…" }

Requires authentication. Signs out every other session and keeps the caller signed in. API tokens are not affected.

GET /api/security/status Live server security posture

Response

{
  "config_encryption": true,
  "secrets": { "mode": "file" },
  "admin_https": false,
  "admin_login": { "password_set": true, "strong_password_policy": true, "require_secure_login": false, "session_idle_timeout": "12h0m0s", "session_max_age": "168h0m0s", "api_tokens": 1 },
  "csp_enforced": true,
  "rate_limit": { "max_requests": 1000, "window_seconds": 60 },
  "allowed_networks_count": 2,
  "godaddy_configured": true,
  "godaddy_base_url": "https://api.godaddy.com",
  "acme_directory": "https://acme-staging-v02.api.letsencrypt.org/directory",

secrets.mode is env (key from PROXYGATE_CONFIG_KEY), file (data/secret.key), disabled or none (nothing stored yet). When stored credentials could not be decrypted, secrets.error and encryption_error explain why.

GET /api/config Get current configuration (secret redacted)

Response

{
  "server": { "http_port": 8080, "https_port": 8443, "admin_port": 9090, "admin_host": "127.0.0.1", "allowed_networks": ["127.0.0.0/8", "::1/128"] },
  "routes": [],
  "godaddy": { "api_key": "...", "api_secret": "********", "base_url": "https://api.godaddy.com" },
  "acme": { "email": "admin@example.com", "directory": "https://acme-staging-v02.api.letsencrypt.org/directory", "cert_dir": "./certs", "use_staging": true },
  "security": { "admin_tls": { "enabled": false }, "require_secure_login": false }
}
PUT /api/config/server Update server ports, host, and CIDR allowlist

Request Body

{
  "http_port": 8080,
  "https_port": 8443,
  "admin_port": 9090,
  "admin_host": "127.0.0.1",
  "allowed_networks": ["127.0.0.0/8", "::1/128"]
}

All fields are optional; omitted fields keep their value. Ports must be 1..65535 and distinct; networks accept CIDR or single IPs. A change that would exclude the caller's own address is refused. Response: { "status": "updated", "restart_required": true } — port, host and network changes apply after a restart.

Proxy Routes

Manage domain and optional path-prefix routes. Duplicate domain + path-prefix combinations return 409 Conflict.

GET /api/routes List all configured routes
POST /api/routes Create a new proxy route

Request Body

{
  "name": "API Gateway",
  "domain": "app.example.com",
  "path_prefix": "/api",
  "target_host": "127.0.0.1",
  "target_port": 8080,
  "tls_enabled": false,
  "enabled": true
}

domain, target_host and target_port are required; id is generated unless you supply one. domain is lowercased; target_host is a hostname or IP (IPv6 with or without brackets). path_prefix is optional and must start with /. enabled defaults to true. tls_enabled requires cert_file and key_file — normally set for you by /api/acme/complete. Returns 201 with the stored route including its id.

GET /api/routes/{id} Fetch a single route by ID
PUT /api/routes/{id} Update an existing route

Partial update: only fields present in the body change, so certificate fields survive an edit that omits them. Same validation as create. Response: { "status": "updated", "route": { … } }.

PATCH /api/routes/{id}/toggle Toggle a route between active and disabled

Response: { "status": "updated", "route": { … } }. Takes effect immediately.

DELETE /api/routes/{id} Delete a route

Returns 404 if the route does not exist. Takes effect immediately.

GET /api/status List enabled routes and whether a certificate is loaded

Response: { "routes": [{ "domain", "route", "active", "has_cert" }], "timestamp" }, built from what the proxy is currently serving.

TLS Certificates (ACME)

Request certificates via DNS-01 challenge and inspect expiry or renewal status.

POST /api/acme/request Start DNS-01 challenge for a domain

Request Body

{ "domain": "app.example.com" }

Response

{
  "domain": "app.example.com",
  "status": "pending",
  "record_name": "_acme-challenge.app.example.com",
  "record_value": "..."
}
POST /api/acme/complete Verify challenge and install certificate

Request Body

{ "domain": "app.example.com", "auto_dns": true }

Without auto_dns, publish the TXT record from /api/acme/request yourself before calling this. With auto_dns (GoDaddy configured) ProxyGate publishes it and waits 30s for propagation before validating, so the call can take a couple of minutes. On success every route on the domain gets tls_enabled, cert_file, key_file and auto_cert set and the certificate is served immediately. Validation failures return 500 with the reason from Let's Encrypt.

Response

{ "status": "certificate obtained", "cert_file": "certs/app.example.com.pem", "key_file": "certs/app.example.com.key" }
GET /api/acme/challenges List recorded ACME challenges
PUT /api/acme/config Update ACME email and staging/production directory

Request Body

{ "email": "admin@example.com", "use_staging": false }

directory is optional and defaults to the Let's Encrypt staging or production URL based on use_staging; any https:// ACME directory is accepted. An empty cert_dir keeps the current one. Applies without a restart; switching directory discards pending challenges.

GET /api/certs/status Get issued certificates, days remaining, and renewal counts

Response

{
  "metrics": { "renewal_success": 3, "renewal_failed": 0 },
  "certs": [{ "domain": "app.example.com", "cert_file": "...", "expires_at": "2027-02-21T08:00:00Z", "days_remaining": 87, "needs_renewal": false, "auto_renew": true }],
  "timestamp": "2026-11-26T08:00:00Z"
}

One entry per domain. ProxyGate checks once a day and renews certificates with 30 days or fewer left. auto_renew is true when that can succeed: the route is enabled and GoDaddy is configured, because renewal publishes the challenge record through GoDaddy. error appears if the certificate file cannot be read.

GoDaddy DNS

Manage GoDaddy domains and DNS records. All endpoints return 400 until GoDaddy credentials are saved.

PUT /api/godaddy/config Save GoDaddy API credentials and environment

Request Body

{
  "api_key": "your-key",
  "api_secret": "your-secret",
  "base_url": "https://api.godaddy.com"
}

Allowed values for base_url: https://api.godaddy.com (production) or https://api.ote-godaddy.com (test environment); the API refuses any other host, so credentials cannot be redirected elsewhere through it. Send an empty or "********" api_secret to keep the stored secret.

POST /api/godaddy/verify Test GoDaddy API connectivity
GET /api/godaddy/domains List active GoDaddy domains

Query Parameters

Returns only ACTIVE domains sorted alphabetically by default. Pass ?include_inactive=true to include expired, cancelled, or transferred domains.

GET /api/godaddy/domains/{domain}/records List DNS records for a domain
POST /api/godaddy/domains/{domain}/records Create a DNS record

Request Body

{ "type": "A", "name": "app", "data": "203.0.113.10", "ttl": 600 }

Types: A, AAAA, CNAME, TXT, MX, NS, CAA (SRV is not supported). ttl defaults to 600 and must be 600–86400. A/AAAA values must be IPv4/IPv6 addresses and CNAME values a hostname. Pass priority for MX records.

DELETE /api/godaddy/domains/{domain}/records/{type}/{name} Delete a DNS record

Removes all values for that type and name.

POST /api/godaddy/auto-dns Create A or CNAME record for a route

Request Body

{ "domain": "example.com", "subdomain": "app", "type": "A", "ip": "203.0.113.10" }

For "type": "CNAME" pass the target hostname in value.

Real-Time Events

Connect over WebSocket to receive JSON broadcasts whenever routes, certificates, DNS records, or configuration change.

GET /ws WebSocket event stream

Event Types

config_changed     Configuration saved (GoDaddy secret masked)
route_added        New proxy route created
route_updated      Route edited or enabled/disabled
route_deleted      Route removed
acme_challenge     DNS-01 challenge created
cert_obtained      TLS certificate issued and linked
dns_record_created GoDaddy DNS record created
dns_record_deleted GoDaddy DNS record deleted
auto_dns_created   Auto-DNS record created

Messages are { "type": "...", "payload": { … } }. Browser connections must come from the admin UI's own origin.
